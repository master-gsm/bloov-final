OPERATION QUEUE (The Engine)
================================================================================

Location: IndexedDB → operation_queue table

Structure of Each Operation:
  {
    operationId: "uuid",              // Unique operation ID
    table: "sales|sale_items",        // Target table
    operation: "insert|update|delete", // Operation type
    data: { /* payload */ },          // Actual data
    localVersion: timestamp,          // When created
    remoteVersion: null,              // Set after sync
    status: "pending|synced|failed",  // Current status
    retries: 0,                       // Attempt counter
    maxRetries: 3,                    // Max attempts
    error: null,                      // Error message
    syncedAt: null,                   // When synced
    serverResponse: null,             // Server response
  }

Lifecycle:
  1. Created (pending)
     ├─ Added when offline
     ├─ Added even if online (batching)
     └─ Stored in IndexedDB

  2. Processing (enhancedSyncManager)
     ├─ Detected when online
     ├─ Batched with others
     └─ Sent to server

  3. Server Processing
     ├─ Received by Supabase
     ├─ Inserted into tables
     ├─ Triggers executed
     └─ Response returned

  4. Synced
     ├─ Mark as synced
     ├─ Store serverResponse
     ├─ Set remoteVersion
     └─ Keep for audit

  5. Cleanup
     ├─ Old synced operations archived
     ├─ Failed operations retried
     └─ Queue stays clean
