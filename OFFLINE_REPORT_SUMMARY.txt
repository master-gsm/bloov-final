Trigger Offline:  startAutoSync() on app init

Auto-Sync Features:
  ✅ Triggered every 5 minutes when navigator.onLine = true
  ✅ Can be manually triggered anytime
  ✅ Auto-triggers on connection restored (300ms delay)
  ✅ Returns success/failed count

Sync Process:
  1. Retrieves pending operations (sorted by timestamp)
  2. Executes each operation with conflict resolution
  3. Removes successful operations from queue
  4. Increments retry count for failures
  5. Notifies all subscribers of status changes

Conflict Resolution:
  INSERT:   If exists → attempts update instead
  UPDATE:   Checks version → local-wins on conflict
  DELETE:   Blocked for immutable tables

Current Method:
  navigator.onLine (browser network status)
  Event listeners: window 'online' / 'offline' events

What It Detects:
  ✅ Network cable/WiFi connected
  ✅ Device has active network interface
  ❌ Does NOT verify internet routing
  ❌ Does NOT verify DNS resolution
  ❌ Does NOT verify Supabase reachability
  ❌ Does NOT ping any server

False Positive Scenarios:
  1. WiFi connected but no internet (airport, firewall)
  2. ISP down but interface up
  3. Firewall blocking Supabase specifically
  4. DNS failure
  5. CDN/Supabase service down

Result:
  System reports "online" but cannot reach Supabase
  → Attempts sync
  → Fails
  → Retries 3 times
  → Deletes operation
  → User loses data silently

Recommendation:
  Implement actual Supabase connectivity verification
  (ping + retry strategy with exponential backoff)
